Один AI-инструмент для кодинга превращается в **самоорганизующуюся софтверную фирму** — тимлид, который командует, 15 лидов направлений, которые оркестрируют, 61 старших специалистов, которые исполняют, и конвейер микрозадач настолько быстрый, что полноценная функция выпускается за минуты, а не часы. Каждое изменение протестировано. Каждое изменение задокументировано. Каждое изменение проверено до того, как коснуться вашей кодовой базы.

**Вы — Директор. Вы решаете, что важно. Всё остальное делает система.**

## 🌋 Проблема, Которую Это Устраняет

Попросите одного AI-ассистента «сделать флоу оформления заказа» — и получите: уверенный монолог, простыню кода, ноль тестов и баги, которые вы находите уже в продакшене.

Причина структурная. Одна модель, делающая всё одновременно, — это **универсал, плохо выполняющий пять работ** — архитектор, инженер, тестировщик, ревьюер и аудитор безопасности слиты в один размытый мозг. Нет ревью. Нет проверки. Нет ответственности.

**Этот проект — лекарство.** Он разбивает этот размытый мозг на **компанию специалистов** — каждый из них старший инженер ровно с одной специализацией, каждый быстр, потому что мал, каждый подотчётен, потому что сдаёт рабочий отчёт, а не пустые обещания.

## 🧠 Почему Это Быстро — Асимметрия Продумана

Большинство «AI-компаний» терпят неудачу, потому что каждый агент — это гигантский промпт, который заново выводит всё сам. Эта система переворачивает классический компромисс:

| Слой | Размер промпта | Почему |
|------|----------------|--------|
| **Специалисты** | Крошечный | Одна микрозадача, одна специализация, **данные с рождения** — ноль исследований |
| **Лиды направлений** | Небольшой | Знают ростер и маршрутизацию своей области — планируют микрозадачи, назначают ID, никогда не запускают |
| **Тимлид** | Огромный (~1400 строк) | Несёт протоколы, матрицу маршрутизации, шлюзы качества, правила эскалации |
| **AGENTS.md** | Средний | Всеобщая конституция, которой подчиняется каждый агент |
| **Skills** | Глубокие, ленивая загрузка | Подтягиваются только когда микрозадача в них нуждается |

**Правило:** маленькие агенты работают быстро → узким местом является инъекция контекста → поэтому контекст несёт тимлид. Хорошо запущенный сотрудник заканчивает **за минуты**. Скорость достигается малым размером.

## 🏭 Конвейер Микрозадач — Почему Он Выпускает

Каждая задача проходит через конвейер, где каждый специалист делает ровно свой шаг и останавливается:

```
КОНТЕКСТ → ДИЗАЙН → РЕАЛИЗАЦИЯ → ТЕСТ → ПРОВЕРКА → ВЫПУСК
  Скаут      Лиды     Инженер    Test-инженер  QA, Code-    Тимлид
           направлений (одна     (одна          Ревьюер,     коммитит
           + дизайнеры  микрзадача)             Security,
                                                 аудиты
```

**Лиды направлений находятся на этапе ДИЗАЙНА:** они разбивают директиву на самые узкие микрозадачи и рекомендуют, какой специалист возьмётся за каждую. Тимлид берёт этот план, сам запускает специалистов и ведёт остальную часть конвейера.

**Законы, которые заставляют это работать:**

- 📦 **Одна сессия = одна микрозадача.** Отдано = сессия окончена. Никакого расширения объёма, никаких «раз уж я здесь».
- 🍼 **Рождаются с данными.** Тимлид вкладывает факты, выдержки кода, радиус последствий и спецификацию в каждый запуск. Сотрудник никогда не исследует кодовую базу сам.
- 📤 **Сообщай, а не чини.** Нашёл баг вне своей специализации? Опиши его в рабочем отчёте. Тимлид замаршрутизирует.
- ⚡ **Скорость — это фича.** Микрозадача, требующая 6+ шагов, была слишком большой — тимлид должен был разбить её.

**Хирургический Workflow** — каждый агент, каждая задача:

```
① ДУМАЙ  →  ② ПЛАНИРУЙ  →  ③ ДЕЙСТВУЙ  →  ④ ПРОВЕРЬ  →  ⑤ СДАЙ → СТОП
```

Самый узкий путь. Один проход. Минимальная проверка. Остановитесь после сдачи.

## 🔐 Дисциплина, Которая Делает Это Не Хаос

Запустить 30 агентов может каждый. Хаос — это легко. **Проверка — вот трудная часть** — и эта система безжалостна к ней:

| Протокол | Что он гарантирует |
|----------|-------------------|
| 🗣️ **FIRCAC** | Факты → Проблема → Правила → Кейсы → Применение → Последствия. Обязательно, вслух, перед каждым исправлением бага или сложным решением. |
| 🔍 **ABC** | **Ничего не предполагай. Никому не верь. Подтверждай всё.** Доктрина проверки — каждое утверждение доказывается, а не принимается на веру. |
| 🧪 **Тест в ОДИН прогон** | Прогони набор один раз, захвати весь вывод. Никогда не перегоняй «за кусочком» результата. |
| 🔴🟢 **КРАСНЫЙ-ЗЕЛЁНЫЙ** | Изменение получает МАКСИМУМ 2 прогона теста. Чините пачками, а не каплями. |
| 🏓 **Один владелец тестов** | Набор запускает только Test Engineer. Остальные потребляют вердикт. Никто не перегоняет чужой «зелёный». |
| 🧠 **Усилители интеллекта** | CodeGraph прежде всего для кода. Tavily перед догадками. Браузер — чтобы реально УВИДЕТЬ UI. AgentMemory для постоянной памяти. **Nushell — главный инструмент работы с данными** (grep, поиск файлов, чтение файлов, JSON/CSV/YAML; bash — только как запасной). |
| 🚦 **Эскалация** | Человеческие решения идут наверх с вариантами + дедлайном. Решения по реализации остаются внутри. Тимлид эскалирует, а не гадает. |
| 📤 **КОНТРАКТ ПЕРЕДАЧИ** | Каждый результат заканчивается Вердикт + Доказательство + Файлы + Следующий владелец. Никто не разбирает свободный текст заново. |
| ✅ **Определение готовности** | Протестировано, задокументировано, чисто по типам, нет мёртвого кода, заполнен контракт передачи. Непротестированная работа — не готова. |
| 🔄 **Старт сессии** | ВСПОМНИ → проверь сессии → опиши состояние → загрузи спек → объяви. Никогда не начинай вслепую. |
| 🚨 **Режим «Я ушёл»** | Скажите «Я ушёл» — компания работает полностью автономно, документирует каждое решение и отчитывается по вашему возвращению. |

## 🔌 Плагины — Невидимая Инфраструктура

Четыре плагина работают тихо на фоне, делая систему умнее незаметно для вас:

| Плагин | Что делает |
|--------|-----------|
| 🧹 **opencode-dynamic-context-pruning** | Динамическая обрезка контекста для удержания в лимитах токенов — агенты никогда не достигают потолка |
| 🔍 **opencode-tool-search** | Умный поиск инструментов — агенты находят нужный инструмент без хардкода |
| 📢 **opencode-notifier** | Отправляет уведомления при завершении задач — вы знаете, когда что-то выпущено |

Настроено в `opencode.jsonc`:
```jsonc

  "opencode-dynamic-context-pruning",
  "opencode-tool-search",
  "@mohak34/opencode-notifier@latest",
  "opencode-auto-resume"
]
```

## 🧠 MCP-Серверы — Расширение Мозга

Два MCP-сервера дают агентам суперсилы за пределами того, что может LLM:

| Сервер | Тип | Что делает |
|--------|-----|-----------|
| **CodeGraph** | Локальный (в комплекте) | Интеллект кода — поиск символов, цепочки вызовов, радиус последствий. Заменяет grep графом знаний. |
| **Tavily** | Удалённый | Веб-поиск, извлечение документации, исследования. Агенты проверяют утверждения вместо догадок. |
| **AgentMemory** | Локальный (в комплекте) | Постоянная память между сессиями — факты, паттерны, решения по архитектуре переживают перезапуски. |

```jsonc
"mcp": {
  "codegraph": {
    "type": "local",
    "command": ["codegraph", "serve", "--mcp"]
  },
  "tavily": {
    "type": "remote",
    "url": "https://mcp.tavily.com/mcp/?tavilyApiKey={file:.secrets/tavily.key}"
  }
}
```

`fircac-out-loud` (рассуждение + проверка ABC) · `find-skills` (обнаружение новых возможностей)

**Мастерство кода:**
`testing-patterns` · `api-patterns` · `error-patterns` · `state-patterns` · `caching-patterns` · `refactoring-patterns` · `performance-patterns` · `algorithm-patterns` · `git-patterns`

`security-patterns` · `compliance-patterns` · `domain-knowledge` · `research-patterns`

**Фронтенд и дизайн:**
`a11y-patterns` · `impeccable` (инструмент дизайна на командах — запусти `context.mjs`, направь в подкоманду; **DESIGN.md — это закон**) · `ux-psychology` (оптимизация конверсии) · `ux-redesign-examples` (паттерны из реальных A/B тестов)

## 🎨 Паттерны Дизайна — Библия Стиля Кода

Компания следует 15 проверенным паттернам дизайна. Полные руководства в [`CODE_STYLE.md`](./CODE_STYLE.md).

| Паттерн | Когда | Антипаттерн, который убивает |
|---------|-------|------------------------------|
| **Инверсия Управления** | Внешние зависимости | Код, который вызывает библиотеки вместо того, чтобы быть вызываемым |
| **Явная Зависимость** | Все зависимости | Скрытое связывание через глобалы, синглтоны или service locators |
| **Парсинг, Не Валидация** | Обработка входа | Рантайм-проверки, которые оставляют типы нетипизированными |
| **Паттерн Трёхсоставного** | Опциональные значения | Путаница null/undefined — Присутствует/Отсутствует/Ошибка |
| **Граница Быстрого Отказа** | Обработка ошибок | Сырые ошибки, просачивающиеся между слоями |
| **Один Уровень Абстракции** | Дизайн функций | Смешивание высокоуровневой оркестрации с низкоуровневыми деталями |
| **Терпимый Читатель** | Внешние данные | Хрупкие парсеры, ломающиеся на неожиданном вводе |
| **Паттерн Значения Ошибки** | Ожидаемые сбои | Исключения для управления потоком — ошибки как значения, никогда throw |
| **Типобезопасный Строитель** | Сложное конструирование | Частично инициализированные объекты, телескопические конструкторы |
| **Антикоррупционный Слой** | Внешние API | Бизнес-логика, спутанная со Stripe/DB/SMTP |
| **Композиция Над Наследованием** | Повторное использование кода | Глубокие иерархии наследования, блокирующие поведение |
| **Объект-Сентинел** | Специальные значения | Магические числа и проверки на null |
| **Паттерн Спецификации** | Бизнес-правила | Рассеянные цепочки if-else |
| **Тип Result** | Ожидаемые сбои | Исключения для управления потоком — Ok/Err, никогда throw |
| **Границы Контекста** | Моделирование домена | Бог-объекты, служащие всему |

**Мета-правило:** Код — это средство коммуникации. Если читатель должен смотреть в реализацию, чтобы понять вызов, абстракция неправильная.

## 🛠️ Скрипты — Инструментарий

Четыре скрипта автоматизируют рабочий процесс контейнера:

| Скрипт | Что делает |
|--------|-----------|
| `launcher.sh` | Запускает контейнер Podman — управляет build, mounts, X11, secrets, маппингом UID |
| `create-project` | Создаёт новый проект opencode — git init, codegraph init, конфиг .opencode |
| `setup-project` | Подключает существующий проект к opencode — OpenSpec + CodeGraph init |
| `first-run.sh` | Точка входа контейнера — запускает pnpm install при первом запуске, затем bash |

**Использование:**
```bash
# Новый проект
create-project my-api --dir ~/projects

# Существующий проект
setup-project /path/to/project

# Контейнер
./scripts/launcher.sh ~/code          # смонтировать папку с проектами
./scripts/launcher.sh --build         # принудительная пересборка
```

## ⚙️ Конфигурация

### opencode.jsonc — Панель Управления

```jsonc
{
  "$schema": "https://opencode.ai/config.json",
  "plugin": ["opencode-dynamic-context-pruning", "opencode-tool-search", "..."],
  "mcp": { "codegraph": { ... }, "tavily": { ... } },
  "default_agent": "team/tech-lead",          // ← Король — ваш агент по умолчанию
  "permission": {
    "external_directory": { "/tmp": "allow", "/home/*/OpencodeImprovements": "allow" },
    "bash": { "* /tmp*": "allow", "*/home/*/OpencodeImprovements*": "allow" }
  }
}
```

| Настройка | Что делает |
|-----------|-----------|
| `default_agent` | Какой агент запускается при старте opencode (по умолчанию: `team/tech-lead`) |
| `permission.external_directory` | Какие директории хоста доступны агентам |
| `permission.bash` | Какие bash-команды агенты могут выполнять без запроса |

### Переменные Окружения

## ⚠️ Жёсткие Правила — Не Обсуждаются

- **Только pnpm.** Никогда npm/npx.

- **Коммитьте только проверенную работу** — на границах фичи, сначала зелёные тесты. Коммит `fix:` означает, что предыдущий коммит выпустил непроверенную работу. Это провал.

## 🔄 Самосовершенствование — Аппарат Улучшается

Любой агент может сообщить о проблемах с самим ИИ-аппаратом. Система улучшается, слушая своих же операторов.

**Директория:** `~/OpencodeImprovements/reports/`

Отчёты пишутся как markdown-файлы по шаблону [REPORT_TEMPLATE.md](~/OpencodeImprovements/REPORT_TEMPLATE.md). Когда агент находит сломанное правило, отсутствующую роль, узкое место в рабочем процессе или проблему конфигурации, он пишет отчёт. Директор проверяет и одобряет изменения. Тимлид их реализует.

**Протокол Саморефлексии** — каждый агент перед сдачей отвечает на 3 вопроса:
1. Исследовал ли я что-то, чего мне не давали?
2. Загрузил ли я скилл, который мне не нужен был?
3. Проверил ли я заново то, что уже было проверено?

**Правило:** аппарат — это код. Он проходит код-ревью. Он улучшается. Агенты — первая линия защиты от вырождения аппарата.

## 📋 Рекомендации — Постоянное Отслеживание Улучшений

Каждый «проходит с рекомендациями» от QA, безопасности, ревью кода или любого агента проверки сохраняется в `recommendations/` — не теряется в истории чата.

```
recommendations/
├── security/          ← улучшения безопасности
├── performance/       ← рекомендации по производительности
├── quality/           ← предложения по качеству кода
├── testing/           ← улучшения тестов
├── accessibility/     ← рекомендации по доступности
├── architecture/      ← улучшения архитектуры
└── general/           ← другие рекомендации
```

**Формат:** `YYYY-MM-DD-topic.md` со Статусом, Приоритетом, Усилием, Обоснованием, Доказательством.

**Команда пользователя:** `«Реализуй все рекомендации»` (или «Реализуй все предыдущие рекомендации») → Тимлид выполняет ПРОТОКОЛ РЕАЛИЗАЦИИ РЕКОМЕНДАЦИЙ: сканирование pending → проверка уже-реализованного → поиск противоречий → группировка по доменам → запуск специалистов → верификация по уровню → удаление файлов по завершении → отчёт. Противоречащие или уже присутствующие рекомендации никогда не реализуются повторно.

Полный протокол: [`recommendations/README.md`](./recommendations/README.md)

## 🧠 AgentMemory — Постоянная Память Между Сессиями

AgentMemory — это автономный MCP-сервер, дающий каждому агенту постоянную память между сессиями:

```
┌─────────────────────────────────────────────────────────┐
│  agentmemory-mcp (MCP-сервер)                           │
│  ├── База данных SQLite с полнотекстовым поиском FTS5   │
│  ├── Предоставляет memory_save, memory_recall и т.д.    │
│  ├── Автокомпакция, поиск и инъекция контекста          │
│  └── Предоставляет ресурсы для просмотра воспоминаний   │
└─────────────────────────────────────────────────────────┘
```

**Типы памяти:** `fact`, `pattern`, `architecture`, `bug`, `workflow`, `preference`

**Когда сохранять:** Решения по архитектуре, первопричины багов, паттерны проекта, предпочтения пользователя, повторяемые процессы.

**Когда вспоминать:** Начало сессии, отладка, перед рефакторингом, перед вопросом к тому, что вы уже должны знать.

## 🚀 Управляйте Компанией — Как Это Чувствуется За Вашим Столом

```
Вы:         Исправь баг оплаты на странице оформления заказа.
Тимлид:     Просит Backend Lead составить план оркестрации → запускает
            Scout → Bug Hunter → Backend Engineer → Test Engineer → QA.
            Отчитывается: первопричина доказана, фикс проверен,
            тесты зелёные, выпущено.
```

**Или полный опыт:**

1. **Дайте директиву** — одну строку. `«Выпусти X»`, `«Исправь Y»`, `«Исследуй Z»`, `«Рефакторинг аутентификации»`.
2. **Тимлид делает всё остальное** — план, команда, ревью, проверка, коммит.
3. **Получите отчёт с доказательствами** — вердикт, прогоны тестов, затронутые файлы, следующий владелец. Не «ощущения».
4. **Скажите `Я ушёл`** → полный автономный режим. Компания работает одна, документирует каждое решение в «Протоколах совета директоров» и отчитывается по вашему возвращению.
5. **Вызовите любого специалиста вручную** — `task team/security/security-engineer` — для точечного ревью в любой момент.
6. **Эскалации приходят как решения**, а не вопросы — варианты, компромиссы, дедлайн.
