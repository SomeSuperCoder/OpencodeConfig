# 🏢 Компания по разработке ПО на Opencode

> **Хватит просить ассистента. Начните управлять компанией.**

Один AI-инструмент для кодинга превращается в **самоорганизующуюся софтверную фирму** — тимлид, который командует, 7 лидов направлений, которые оркестрируют, 43 старших специалиста, которые исполняют, и конвейер микрозадач настолько быстрый, что полноценная функция выпускается за минуты, а не часы. Каждое изменение протестировано. Каждое изменение задокументировано. Каждое изменение проверено до того, как коснуться вашей кодовой базы.

**Вы — Директор. Вы решаете, что важно. Всё остальное делает система.**

---

## 🌋 Проблема, Которую Это Устраняет

Попросите одного AI-ассистента «сделать флоу оформления заказа» — и получите: уверенный монолог, простыню кода, ноль тестов и баги, которые вы находите уже в продакшене.

Причина структурная. Одна модель, делающая всё одновременно, — это **универсал, плохо выполняющий пять работ** — архитектор, инженер, тестировщик, ревьюер и аудитор безопасности слиты в один размытый мозг. Нет ревью. Нет проверки. Нет ответственности.

**Этот проект — лекарство.** Он разбивает этот размытый мозг на **компанию специалистов** — каждый из них старший инженер ровно с одной специализацией, каждый быстр, потому что мал, каждый подотчётен, потому что сдаёт рабочий отчёт, а не пустые обещания.

## 🧠 Почему Это Быстро — Асимметрия Продумана

Большинство «AI-компаний» терпят неудачу, потому что каждый агент — это гигантский промпт, который заново выводит всё сам. Эта система переворачивает классический компромисс:

| Слой | Размер промпта | Почему |
|------|----------------|--------|
| **Специалисты** | Крошечный | Одна микрозадача, одна специализация, **данные с рождения** — ноль исследований |
| **Лиды направлений** | Небольшой | Знают ростер и маршрутизацию своей области — планируют микрозадачи, назначают ID, никогда не запускают |
| **Тимлид** | Огромный (~1400 строк) | Несёт протоколы, матрицу маршрутизации, шлюзы качества, правила эскалации |
| **AGENTS.md** | Средний | Всеобщая конституция, которой подчиняется каждый агент |
| **Skills** | Глубокие, ленивая загрузка | Подтягиваются только когда микрозадача в них нуждается |

**Правило:** маленькие агенты работают быстро → узким местом является инъекция контекста → поэтому контекст несёт тимлид. Хорошо запущенный сотрудник заканчивает **за минуты**. Скорость достигается малым размером.

## 🏭 Конвейер Микрозадач — Почему Он Выпускает

Каждая задача проходит через конвейер, где каждый специалист делает ровно свой шаг и останавливается:

```
КОНТЕКСТ → ДИЗАЙН → РЕАЛИЗАЦИЯ → ТЕСТ → ПРОВЕРКА → ВЫПУСК
  Скаут      Лиды     Инженер    Test-инженер  QA, Code-    Тимлид
           направлений (одна     (одна          Ревьюер,     коммитит
           + дизайнеры  микрзадача)             Security,
                                                 аудиты
```

**Лиды направлений находятся на этапе ДИЗАЙНА:** они разбивают директиву на самые узкие микрозадачи и рекомендуют, какой специалист возьмётся за каждую. Тимлид берёт этот план, сам запускает специалистов и ведёт остальную часть конвейера.

**Законы, которые заставляют это работать:**

- 📦 **Одна сессия = одна микрозадача.** Отдано = сессия окончена. Никакого расширения объёма, никаких «раз уж я здесь».
- 🍼 **Рождаются с данными.** Тимлид вкладывает факты, выдержки кода, радиус последствий и спецификацию в каждый запуск. Сотрудник никогда не исследует кодовую базу сам.
- 📤 **Сообщай, а не чини.** Нашёл баг вне своей специализации? Опиши его в рабочем отчёте. Тимлид замаршрутизирует.
- ⚡ **Скорость — это фича.** Микрозадача, требующая 6+ шагов, была слишком большой — тимлид должен был разбить её.

**Хирургический Workflow** — каждый агент, каждая задача:

```
① ДУМАЙ  →  ② ПЛАНИРУЙ  →  ③ ДЕЙСТВУЙ  →  ④ ПРОВЕРЬ  →  ⑤ СДАЙ → СТОП
```

Самый узкий путь. Один проход. Минимальная проверка. Остановитесь после сдачи.

## 🔐 Дисциплина, Которая Делает Это Не Хаос

Запустить 30 агентов может каждый. Хаос — это легко. **Проверка — вот трудная часть** — и эта система безжалостна к ней:

| Протокол | Что он гарантирует |
|----------|-------------------|
| 🗣️ **FIRCAC** | Факты → Проблема → Правила → Кейсы → Применение → Последствия. Обязательно, вслух, перед каждым исправлением бага или сложным решением. |
| 🔍 **ABC** | **Ничего не предполагай. Никому не верь. Подтверждай всё.** Доктрина проверки — каждое утверждение доказывается, а не принимается на веру. |
| 🧪 **Тест в ОДИН прогон** | Прогони набор один раз, захвати весь вывод. Никогда не перегоняй «за кусочком» результата. |
| 🔴🟢 **КРАСНЫЙ-ЗЕЛЁНЫЙ** | Изменение получает МАКСИМУМ 2 прогона теста. Чините пачками, а не каплями. |
| 🏓 **Один владелец тестов** | Набор запускает только Test Engineer. Остальные потребляют вердикт. Никто не перегоняет чужой «зелёный». |
| 🧠 **Усилители интеллекта** | CodeGraph прежде всего (никогда grep). Tavily перед догадками. Браузер — чтобы реально УВИДЕТЬ UI. AgentMemory для постоянной памяти. Nushell для структурированных данных. |
| 🚦 **Эскалация** | Человеческие решения идут наверх с вариантами + дедлайном. Решения по реализации остаются внутри. Тимлид эскалирует, а не гадает. |
| 📤 **КОНТРАКТ ПЕРЕДАЧИ** | Каждый результат заканчивается Вердикт + Доказательство + Файлы + Следующий владелец. Никто не разбирает свободный текст заново. |
| ✅ **Определение готовности** | Протестировано, задокументировано, чисто по типам, нет мёртвого кода, заполнен контракт передачи. Непротестированная работа — не готова. |
| 🔄 **Старт сессии** | ВСПОМНИ → проверь сессии → опиши состояние → загрузи спек → объяви. Никогда не начинай вслепую. |
| 🚨 **Режим «Я ушёл»** | Скажите «Я ушёл» — компания работает полностью автономно, документирует каждое решение и отчитывается по вашему возвращению. |

## 🏛️ Штат — 43 Специалиста, У Каждого Одна Специализация

Каждый агент — **старший инженер с единственной специализацией** — он делает свою работу лучше любого универсала, потому что это всё, что он умеет. Субординация встроена в структуру файлов: `agents/team/` — это компания, каждое направление живёт в своей папке, а лиды направлений советуют тимлиду по оркестрации.

**👑 Король**
`tech-lead` — оркестратор. Единственный, кто решает и запускает.

**🧑‍💼 Лиды направлений (советующие — они планируют, запускаешь ты)**
`team/lead/frontend-lead` · `backend-lead` · `quality-lead` · `security-lead` · `platform-lead` · `product-lead` · `research-lead`

**🎯 Оркестрация и суждения**
`team/core/scout` (глаза — собирает контекст) · `team/core/wise-old-man` (совет по сложным решениям) · `team/product/product-understander` (ЗАЧЕМ это) · `team/product/requirements-analyst` · `team/product/software-architect` · `team/backend/api-designer` · `team/quality/critique` (разрушает дизайны до того, как их построят)

**💻 Направление Frontend** (`team/frontend/`)
`frontend-engineer` · `frontend-ui-designer` (вид) · `ux-designer` (флоу, доступность) · `frontend-animations-engineer` (движение) · `design-system-engineer` · `i18n-engineer`

**⚙️ Направление Backend** (`team/backend/`)
`backend-engineer` · `api-designer` · `database-engineer` (схема + миграции) · `data-engineer` (продуктовая модель данных) · `integration-engineer` · `llm-engineer`

**🧪 Направление Quality** (`team/quality/`)
`test-engineer` (владеет набором тестов) · `qa-engineer` (приёмка) · `code-reviewer` (ревью + статический анализ) · `bug-hunter` (доказывает первопричину с репро до того, как кто-то что-то чинит) · `critique`

**🔒 Направление Security** (`team/security/`)
`security-engineer` (оборона) · `team/security/pentest/*` — набор этичного хакинга (ОТКЛЮЧЁН по умолчанию)

**🚀 Направление Platform** (`team/platform/`)
`devops-engineer` · `observability-engineer` · `performance-engineer`

**🔬 Направление Research** (`team/research/`)
`research-agent` · `domain-expert` · `documentation-writer` · `skill-generator`

**👁️ Vision Reader** (`team/core/vision-reader`) — единственный агент с глазами. Все остальные специалисты работают на текстовой модели; он работает на MiMo (с поддержкой зрения) и читает фото, скриншоты, диаграммы и мокапы интерфейсов для всей команды.

**🛡️ Набор этичного хакинга (ОТКЛЮЧЁН по умолчанию)** — `team/security/pentest/pentest-lead` · `pentest-recon` · `pentest-webapp` · `pentest-exploitation`. Авторизованная команда оценки безопасности: картографирует целевую область, проверяет её инструментами пентеста (nmap, sqlmap, nuclei, ручное тестирование в стиле OWASP) и подтверждает находки минимальными обратимыми PoC. Набор **никогда не подключается по своей инициативе** — он активируется **только когда вы явно просите** о пентесте или оценке безопасности. Повседневная безопасность — за 🔒 Security Engineer.

> **Паттерн недоиспользования:** «Скаута + Backend + QA достаточно». Это не так. Каждый специалист существует, потому что универсал делает эту работу хуже. **Маршрутизируйте по задаче, а не по привычке.**

## 🧰 Арсенал — Skills, Загрузка По Требованию

17 паттерн-скиллов, никогда не загружаются заранее, подтягиваются в тот момент, когда они нужны микрозадаче:

`fircac-out-loud` (рассуждение + проверка) · `testing-patterns` · `api-patterns` · `error-patterns` · `state-patterns` · `caching-patterns` · `refactoring-patterns` · `security-patterns` · `a11y-patterns` · `algorithm-patterns` · `domain-knowledge` · `compliance-patterns` · `git-patterns` · `research-patterns` · `performance-patterns` · `find-skills` · `impeccable` (стандарт дизайна — **DESIGN.md — это закон** для каждого frontend-агента)

**Принцип рассеивания:** AGENTS.md = универсальный минимум. Skills = глубокие, редкие, по требованию. Агенты = только то, что специфично для роли. Тимлид — единственное исключение: его протоколы живут инлайново, потому что он использует их в каждой сессии.

## 🚀 Управляйте Компанией — Как Это Чувствуется За Вашим Столом

```
Вы:         Исправь баг оплаты на странице оформления заказа.
Тимлид:     Просит Backend Lead составить план оркестрации → запускает
            Bug Hunter → Backend Engineer → Test Engineer → QA.
            Отчитывается: первопричина доказана, фикс проверен,
            тесты зелёные, выпущено.
```

**Или полный опыт:**

1. **Дайте директиву** — одну строку. `«Выпусти X»`, `«Исправь Y»`, `«Исследуй Z»`, `«Рефакторинг аутентификации»`.
2. **Тимлид делает всё остальное** — план, команда, ревью, проверка, коммит.
3. **Получите отчёт с доказательствами** — вердикт, прогоны тестов, затронутые файлы, следующий владелец. Не «ощущения».
4. **Скажите `Я ушёл`** → полный автономный режим. Компания работает одна, документирует каждое решение в «Протоколах совета директоров» и отчитывается по вашему возвращению.
5. **Вызовите любого специалиста вручную** — `task team/security/security-engineer` — для точечного ревью в любой момент.
6. **Эскалации приходят как решения**, а не вопросы — варианты, компромиссы, дедлайн.

## ⚠️ Жёсткие Правила — Не Обсуждаются

- **Только pnpm.** Никогда npm/npx.
- **Проверяйте Justfile** перед ручными командами.
- **Коммитьте только проверенную работу** — на границах фичи, сначала зелёные тесты. Коммит `fix:` означает, что предыдущий коммит выпустил непроверенную работу. Это провал.
- **Никогда не используйте встроенный агент `explore`.** Используйте `team/core/scout`.
- **Оставайтесь в своей специализации.** Сообщайте о проблемах; никогда не чините чужую работу.
- **Эмодзи обязательны во всех выводах** — они направляют взгляд читателя на главное.
